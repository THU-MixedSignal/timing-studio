# 时序工坊

将用户描述转换为可编辑时序，让用户在窗口中微调，再从同一工程继续协作。使用已维护的源码和导出器，不启动原生桌面 EXE、不重新手写一套 VA 事件逻辑。

## 环境与入口

所有路径以本文件实际所在的 skill 目录为准，不依赖固定盘符、用户名或当前工作目录。入口为 `scripts/timing_studio.py`；Windows 可用 `scripts/run.cmd` 自动选择 Python 3.12+，缺少时从 python.org 下载并校验私有 Python。下载可能需要网络；已有合适运行时后，窗口与 VA 导出完全在本机工作。窗口要求 Windows 10/11 x64 和 Edge/Chrome；其他平台的图形窗口未验证。自然语言理解由调用此 skill 的助手完成，窗口本身没有聊天模型。

先运行 `scripts/run.cmd doctor` 或 `python -B scripts/timing_studio.py doctor` 检查运行时和浏览器。发行包内的模型与窗口在 `scripts/runtime/`；开发仓库的入口会自动定位项目源码。源码缺失就报告，不另写 VA 导出器。环境变量 `TIMING_STUDIO_PYTHON` 可指定解释器，`TIMING_STUDIO_RUNTIME_DIR` 可指定私有 Python 的安装目录。遵守用户磁盘和目录偏好，在用户选定的可写目录存放请求和会话，不在安装目录自动创建工程，也不接触其他工具的会话。

## 生成与打开

1. 根据请求确定整个大周期、各路初态/跳变/重复范围、公共电平和 rise/fall；沿用已有工程参数，缺少关键值时简短说明假设或询问。界面高低电平不是实际模拟电压。先读 [工程格式与语义](references/project-format.md) 再构造候选 JSON。用整数 fs 和 `model.parse_time()`，通过循环生成成百上千个脉冲，不要求用户逐个绘制。输出普通 segment，不恢复重复块编辑 UI。
2. 在选定的数据目录下用 `requests/<任务名-时间>/` 保存描述、生成脚本和候选 `.timing.json`，用 `sessions/<任务名-时间>/` 建新会话。使用绝对路径。修改已有任务时先读取实际会话，不能把示例会话当成新任务的目标；不因会话名相似而覆盖它。
3. 校验候选文件并生成 VA 检查，再启动窗口。校验和可直接执行的命令见 [会话操作](references/session-workflow.md)。新会话需要显式 `--session` 与 `--project`；恢复已有会话只传 `--session`。启动成功后报告实际会话位置、简短参数和假设，不暴露本机连接令牌。
4. 说明用户可以拖动边沿、精确输入 `1n` / `200p`、用密集概览局部放大，微调至“已保存”后回聊天说“改好了”。窗口不自动给聊天发消息；“已启动后台”“已请求打开窗口”“用户确认看到窗口”要如实区分。

## 继续协作与导出

- 读取最新 state 并记录 `revision`；它含 `project`，不是可直接导入的工程文件。保留用户已改波形、signal ID、创建/端口顺序、显示顺序及设置。小范围变更优先提交单个 edit；整体重建需基于刚读到的 project，保留未要求改动的内容。
- 提交 edit/replace/export 必须携带刚读取的 revision。409 时重新读、比较并重新评估，不把旧候选换个 revision 强行提交。保存状态无法确认时先读回核对，不盲目重复操作。不得直接写 `head.json` 或历史快照。
- signal 的显示顺序与 VA 端口顺序分离；拖动合并会改变 item ID，所以重新读取后再定位边沿。用户手改的某一次脉冲不会自动关联“所有重复周期”；修改整个重复序列时识别并保留例外，意图不清时询问范围。
- 导出使用当前 revision，交付生成的 `.va` 和对应 `.timing.json` 路径，并总结本次实际变更与关键边沿。窗口闭合/后台过期后可从保存会话恢复；不重置初始示例。
- 本 skill 负责本机生成和编辑。用户要求真实仿真时使用其实际可用、已授权的仿真环境；不要求安装特定实验室 skill，不自带服务器配置。不能把本地校验称为 Spectre 验证。
